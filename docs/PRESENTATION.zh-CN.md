# 给客户看的 BoxLite 隔离演示

## 一句话介绍

用两个真实运行的弹球游戏，对比“两个任务共用一个环境”和“每个任务有独立 Box”时，一次错误操作会影响多大范围。

## 开场可以这样说

“假设我们有两个任务同时运行。左边是任务 A，右边是任务 B。先让它们共用同一个环境，再故意触发一次有问题的进程清理，看看另一个任务会不会受影响。接着换成独立 Box，重复完全相同的操作。”

## 两分钟演示顺序

1. 双击 Mac 启动脚本。系统弹窗里的 Key 可以留空；此版本在本机运行，不需要云端账户。
2. 点击页面的「带我看一遍」，自动完成两种场景；也可以逐个手动操作。
3. 共享环境：指出两个游戏的 Box ID 相同、PID 不同。两局都在实际运行，帧计数持续增加。A 触发故障后，两局一起停止。
4. 独立环境：指出两个游戏的 Box ID 不同。重复相同故障，A 停止，B 的画面和真实帧计数继续推进。
5. 展开页面中的正常代码与故障代码，需要时下载本轮 JSON 证据。

可以这样收尾：“当一个任务出错时，我们希望影响停留在它自己的执行环境。BoxLite 让每个任务有自己的微型虚拟机；这个演示把任务之间的边界直接展示出来。”

## 回答客户常见问题

**这是真实运行，还是动画？**

Python 游戏进程在 Box 中计算位置、碰撞和分数。网页读取真实状态并绘图；Box ID、PID 和帧计数可以核对，结果可下载。

**共享模式是不是完全没用 BoxLite？**

两种模式都用 BoxLite。共享模式把两局放在同一个 Box，代表共用环境的任务；独立模式把两局放进不同 Box。这个演示说明的是隔离边界，不是“其他所有方案都不安全”。

**故障到底做了什么？**

同一段固定清理代码会停止 A 所在 Box 内登记的演示游戏进程。它不会扫描本机任意进程，也不是让整个 Box 崩溃。共享模式的 B 在同一个进程清理范围里；独立模式的 B 在另一台 Box 内。

**Key 有什么用？**

本机版本不调用 Cloud API，Key 可留空。弹窗输入保留为可选本机配置，填写后也不会切换到对应账户的云端环境；Key 不进入网页或 Box。不要把“输入了 Key”介绍成“已连接云端”。

**能发给客户运行吗？**

可以分享 GitHub 发布页或 Mac ZIP。此包支持 Apple Silicon Mac，需 Python 3.10+，首次联网下载依赖和基础镜像。客户在自己的机器上运行，不是访问你电脑上的 localhost 地址。

**演示结束怎么关？**

在启动窗口按 Ctrl+C。单次会话最长 15 分钟，结束会停止本机 Box，保留镜像缓存和本地数据，下次可再次启动。

## 上台前

提前运行一次，让 SDK 和镜像完成下载。演示时保持启动窗口开启；在新会话中点击「带我看一遍」。使用自己的屏幕分享展示，或发送正式发布包；不要打包本机运行数据目录。
